# Abstract

Apache Spark jobs usually run under one fixed configuration, although the best setting shifts with operator mix, data scale and skew. This case study presents AdaSpark, a self-adaptive big data programming framework whose reinforcement learning agent selects shuffle partitions and execution parallelism before each run and learns from measured outcomes within a hard budget of 500 training executions. Its monitor–analyze–plan–execute loop never rewards failed configurations, seals test data until evaluation and keeps every decision traceable. On a frozen single-node testbed with five workload families at three data scales, configuration choice moved median execution time by at least 10% on all four families tested, and training used 483 of the budgeted executions with no failed submitted configuration. In a pre-registered confirmatory evaluation on 42 frozen test cells, the learned policy was 4.0 times faster than Spark defaults (significantly, by at least 10%, on 36 of 37 decidable cells) but 1.22 times slower than a tuned static configuration, to which a rule heuristic and equal-budget random search also resolved, so superiority over these baselines was rejected. Policies trained from different seeds disagreed on training states, and generalization was not evaluable. A 1 Hz system sampler kept monitoring overhead below 5% on six of seven cells in two studies, whereas an earlier pass for the Spark event log was not re-established. A pre-registered prediction that interval width shrinks with the square root of the repetition count failed on all seven cells because repetitions were serially correlated.
