# Dataset README — AdaSpark Approved Data Substrate (Day 14)

## What datasets exist

30 physical datasets under `<SPARKRL_DATA_ROOT>/generated/datasets/`, each
containing two Parquet tables (`orders`, `lineitem`) generated from the frozen
canonical schema (`datagen-v1`, Day 13). Physical datasets are named
`skew{skew}_{scale}_s{seed}`:

| ID pattern | skew | scale | seed |
|---|---|---|---|
| `skew1_small_s0` … `skew1_small_s4` | 1.0 | small | 0–4 |
| `skew1_medium_s0` … `skew1_medium_s4` | 1.0 | medium | 0–4 |
| `skew1_large_s0` … `skew1_large_s4` | 1.0 | large | 0–4 |
| `skew1.5_small_s0` … `skew1.5_small_s4` | 1.5 | small | 0–4 |
| `skew1.5_medium_s0` … `skew1.5_medium_s4` | 1.5 | medium | 0–4 |
| `skew1.5_large_s0` … `skew1.5_large_s4` | 1.5 | large | 0–4 |

## Family definitions

Logical families (5) map onto physical data by skew — differentiation is in
the workload query logic (Day 15+), never in the data:

| Family | Description (frozen PLAN §11) | Physical skew |
|---|---|---|
| F1_agg | Aggregation | 1.0 |
| F2_join | Join | 1.0 |
| F3_rdd | RDD sort + filter + reduceByKey | 1.0 |
| F4_ski | Skewed join (extreme skew) | **1.5** |
| F5_mixed | Mixed 3-phase | 1.0 |

F1/F2/F3/F5 share the skew=1.0 physical datasets (75 logical entries → 30
physical datasets; no 3 GB duplication). F4 uses dedicated skew=1.5 data.

## Scale definitions

| Scale | lineitem rows | orders rows | raw target |
|---|---|---|---|
| small | 3,000,000 | 750,000 | ~0.3 GB |
| medium | 10,000,000 | 2,500,000 | ~1 GB |
| large | 30,000,000 | 7,500,000 | ~3 GB |

`micro` (5,000 lineitem rows) is a fixture-only scale used by tests; it is NOT
part of the research ladder and is not generated by the Day-14 matrix.

## Seed policy

Seeds {0, 1, 2, 3, 4} follow PLAN §16/§18: {0,1,2} train, {3} validation,
{3,4} test. Same (family, scale, seed) ⇒ same canonical content and checksum.

## Physical data location

`<SPARKRL_DATA_ROOT>/generated/datasets/<id>/{orders,lineitem}/{data/*.parquet, manifest.json}`

`SPARKRL_DATA_ROOT` defaults to `./data` (excluded from Git) or the external
root resolved by `src/sparkrl/utils/paths.py` / DEC-002 convention. Never
machine-specific absolute paths in code or manifests.

## How to reproduce

```bash
# one physical dataset (both tables)
python scripts/generate_dataset_matrix.py --scale small --seed 0 --skew 1.0

# the full approved matrix (idempotent; skips valid datasets)
python scripts/generate_dataset_matrix.py

# plan only
python scripts/generate_dataset_matrix.py --plan-only
```

Generation is chunked (default 100,000 rows) with bounded memory; each table
gets a manifest.json (checksum + generation fingerprint). Reruns skip valid
datasets and regenerate/quarantine only missing or corrupt tables.

## How to validate

```bash
# after a full run, the driver writes index.json + summary.json:
python -c "import json; d=json.load(open('data/generated/summary.json')); print(d)"
```

* Dataset inventory: `data/generated/index.json` (physical + logical).
* Actual sizes + status: `data/generated/summary.json`.
* Full validation of a table: `sparkrl.datagen.validate.full_validation`.

## Approximate actual sizes

Recorded in `docs/DATASET_INVENTORY.md` and `docs/research/DAY14_DATASET_AUDIT.md`
from actual manifests (parquet-compressed, not raw). Rough guide: each
small dataset ≈ 37–39 MB, medium ≈ 110–120 MB, large ≈ 330–360 MB
(details in the audit).

## Checksum verification

Checksums are FNV-1a 64-bit over canonical row content (NOT parquet bytes;
writer metadata differs). Same spec ⇒ same generation fingerprint + checksum.
See `docs/day13_data_generation.md` for the checksum definition.

## Generator version

`datagen-v1` (schema + generator). The Day-14 matrix adds the batch driver
`scripts/generate_dataset_matrix.py`; generation code remains
`src/sparkrl/datagen/` as frozen on Day 13.
